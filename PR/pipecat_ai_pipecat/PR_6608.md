## PR 描述

## What

`load_config_from_file()` reads the project config with `open(path)` and no encoding, so it decodes with `locale.getencoding()` — UTF-8 on Linux/macOS, the ANSI code page on Windows. A config that the CLI itself writes as UTF-8 therefore cannot be loaded again on Windows as soon as it contains any non-ASCII text (a bot name with an accent, a description in another language):

```python
path.write_text('{"project": {"name": "café — 测试"}}', encoding="utf-8")

load_config_from_file(path)
# UnicodeDecodeError: 'gbk' codec can't decode byte 0x94 in position 30: illegal multibyte sequence
```

`config.json` is user-authored (the CLI scaffold writes it, people edit it), so this is the same class of failure as the manifest read fixed in #6606.

## Change

```diff
-    with open(path) as f:
+    with open(path, encoding="utf-8") as f:
         return json.load(f)
```

Plus a regression test next to the existing loader tests:

```python
def test_load_file_with_non_ascii_content(self, tmp_path):
    """A config written as UTF-8 with non-ASCII text loads unchanged."""
    config_file = tmp_path / "config.json"
    config_file.write_text(
        json.dumps({"project_name": "café — 测试"}, ensure_ascii=False),
        encoding="utf-8",
    )

    loaded = load_config_from_file(config_file)
    assert loaded["project_name"] == "café — 测试"
```

## Not in this PR

A scan of `src/pipecat` still finds a few text-mode opens without an encoding; they are left out on purpose:

- `classifiers/tone/model.py`, `expressive/processors/tone_tagger/model.py` — read a third-party model's `config.json`; worth fixing, but proving it needs a real model directory.
- `evals/_session_subprocess.py` and `runner/run.py` — the payloads are produced by `json.dumps(...)` with its default `ensure_ascii=True`, so those files are ASCII-only and safe under any codec.
- `cli/commands/init.py` — the log file is shared with a child process through a dup'd descriptor; changing only the parent's encoding would desynchronise it from what the child writes, so it needs its own decision.
