## PR 描述

## What

The two Pipecat Tone model loaders read the model folder's `config.json` without an encoding:

```python
self.config = json.loads((model_dir / "config.json").read_text())
```

`read_text()` with no argument decodes with `locale.getencoding()` — UTF-8 on Linux/macOS, the ANSI code page on Windows. A model folder whose `config.json` carries any non-ASCII metadata (author, description, a non-Latin name) therefore cannot be loaded on Windows:

```python
model_dir = Path(tempfile.mkdtemp())
(model_dir / "config.json").write_text(
    json.dumps({"max_len": 64, "name": "语调 — reader"}, ensure_ascii=False), encoding="utf-8"
)

PipecatToneReaderModel(model_dir)
# UnicodeDecodeError: 'gbk' codec can't decode byte 0xad in position 27: illegal multibyte sequence
```

It fails before the tokenizer or the ONNX session is touched, so the whole feature is unusable for that model on Windows — and nothing in the message points at the encoding.

Both copies are affected, with the identical line:

- `src/pipecat/classifiers/tone/model.py:54` (`PipecatToneReaderModel`)
- `src/pipecat/expressive/processors/tone_tagger/model.py:49` (`PipecatToneTaggerModel`)

## Change

```diff
-        self.config = json.loads((model_dir / "config.json").read_text())
+        self.config = json.loads((model_dir / "config.json").read_text(encoding="utf-8"))
```

Two lines. No behaviour change on POSIX, where UTF-8 is already the default; `config.json` is UTF-8 by construction (it is JSON metadata shipped alongside the weights).
