## PR 描述

## What

`SUMMARY_TOKEN_BUFFER` is declared at module level with the comment *"Keep summary at 80% of available space for safety"*, but nothing read it. The two places that apply that 80% wrote the literal instead:

- `LLMAutoContextSummarizationConfig.__post_init__`
- `LLMContextSummarizationConfig.__post_init__` (deprecated, same logic)

So editing the constant did nothing, and the comment above each `* 0.8` — *"Use 80% of max_context_tokens as a reasonable default"* — pointed at a knob that was not connected. This changes both sites to use the constant. The value is identical, so behaviour is unchanged.

## Why it matters

A reader who finds `SUMMARY_TOKEN_BUFFER = 0.8` will assume it controls the buffer and change it; nothing happens, and the search for why costs more than the fix. The same file also carries `MIN_SUMMARY_TOKENS = 100`, which I left alone: there is no clamping logic that could consume it, so removing or wiring it is a product decision, not a cleanup.

## How it was found

Scanned for module-level constants whose name appears exactly once in the repository (excluding `__all__` exports and names mentioned in docs). Five came up in `src/`; three are prompt strings rendered at import time, and of the two token constants only this one has a call site that should use it.
