## PR 描述

### What

Five places document a return value that nothing returns.

**`src/pipecat/services/inworld/tts.py`** — the four websocket lifecycle overrides:

```python
async def _connect(self):
    """Connect to the Inworld WebSocket TTS service.

    Returns:
        The websocket.
    """
    await super()._connect()
    ...
```

`_connect`, `_disconnect`, `_connect_websocket` and `_disconnect_websocket` all return `None`; `_connect_websocket` has one bare `return`. The method that does return the websocket is `_get_websocket()`, whose docstring says the same thing and is correct — it is left untouched.

**`src/pipecat/transports/daily/transport.py`** — `register_audio_destination()` says:

```
Returns:
    True if the audio frame was written successfully, False otherwise.
```

That sentence belongs to the neighbouring `write_audio_frame()`, which does return the bool. `register_audio_destination()` just forwards to `self._client.register_audio_destination(destination)`.

**`examples/getting-started/04-sync-speech-and-image.py`** — `run_bot(transport, runner_args)` still documents the `webrtc_connection` / `room_name` signature it had before the examples moved to the `create_transport()` + `runner_args` form used everywhere else.

### How they were found

An AST pass over the tree comparing each docstring's documented parameter names against the real signature, and `Returns:` sections against functions that never return a value. Two filters keep it honest:

- `self` / `cls` are receivers, not parameters, so documenting them is style, not drift.
- interface methods (`raise NotImplementedError` or docstring-only bodies) document a contract, so their `Returns:` is correct. Without that filter the same scan reports 50 hits in `src/`, almost all of them ABCs.

Result on the whole tree (1625 Python files):

```
before: stale-args=5   bogus-returns=5   (of which the example is the only stale-args)
after : stale-args=0   bogus-returns=0
```

Note the AIC filter methods (`start`, `stop`, `process_frame`) say `Returns: None`, which is accurate for a `None` return and is deliberately not touched.
