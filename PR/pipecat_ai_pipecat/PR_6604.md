## PR 描述

## What

`scripts/provider-watch/*` and its test read and write text files without an explicit encoding, so on Windows they use the ANSI code page (GBK on this machine) instead of UTF-8. The scripts parse the repository's own UTF-8 sources and docs, so the first non-ASCII byte kills them:

```
E   UnicodeDecodeError: 'gbk' codec can't decode byte 0x94 in position 6683: illegal multibyte sequence
```

That is `inventory.py` running `ast.parse(path.read_text(), ...)` over `src/pipecat/**/*.py`, which contains em dashes and curly quotes.

## Change

Adds `encoding="utf-8"` to every `read_text()` / `write_text()` in `scripts/provider-watch/{digest,inventory,publish}.py` and `tests/test_provider_watch_scripts.py` (24 call sites), so reads and writes agree on one encoding on every platform. No behaviour change on POSIX.

## Evidence

Same command, same checkout, Windows 11 / CPython 3.13 / pipecat installed editable:

```
$ pytest tests/test_provider_watch_scripts.py -q

# before
5 failed, 14 passed, 22 errors

# after
2 failed, 39 passed
```

All 22 errors and 3 of the 5 failures are the encoding problem. The 2 remaining failures are environment, not code:

```
E   ModuleNotFoundError: No module named 'pipecat_resampler'
    src/pipecat/audio/resamplers/sinc_stream_resampler.py:17
```

`probe.py` imports `pipecat`, which imports the resampler, so those two tests need the `resamplers` extra; they fail identically before this change and are untouched by it.

`ruff check` and `ruff format --check` are clean on the four files.

## Scope

Tooling only — `scripts/provider-watch/` and its test. Nothing under `src/pipecat/` is touched, so no runtime behaviour, no public API, no docs page changes.

Found while running the suite on Windows to look for platform-specific test failures; the same class of defect (file IO relying on the platform default encoding) is worth a separate sweep if you want one.
