## PR 描述

### Problem or current behavior

Fixes #6225.

A host process that embeds Inspect — running `eval_async()` inside its own Rich `Progress` or `Live` — got `IndexError: pop from empty list` when leaving that context, after the eval itself had finished successfully. Nothing about the eval is wrong; the exception fires on `Progress.__exit__`:

```text
File "rich/progress.py", line 1190, in __exit__
    self.stop()
File "rich/live.py", line 168, in stop
    self.console.pop_render_hook()
File "rich/console.py", line 854, in pop_render_hook
    self._render_hooks.pop()
IndexError: pop from empty list
```

`rich_initialise()` calls `rich.reconfigure(...)`, which reinitializes the process-global console: the `_render_hooks` and `_live_stack` lists that the host's context registered are emptied, so the host's `Live.stop()` has nothing to pop.

### Result or new behavior

The two lists are carried across the reconfigures, so a `Live` or `Progress` that was started before the eval can be stopped afterwards. Offline reproduction (mock model, no provider calls) from the issue, on this machine:

```text
before: raised on leaving the caller's Progress: IndexError - pop from empty list
after:  eval status: success / no IndexError on leaving the caller's Progress
```

### Compatibility and migration

No migration required. Inspect's own display hooks are registered after `rich_initialise()` runs, so its display behavior is unchanged; the restored lists hold only what the host registered beforehand. Nothing public is added or renamed, and no persisted format changes.
