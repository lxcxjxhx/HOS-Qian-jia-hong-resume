## PR 描述

### Motivation & Context

`python-test-coverage.yml` lists `python/tests/unit/**` in both `pull_request.paths` and `push.paths`. That directory has never existed:

```console
$ ls python/tests
samples
$ git log --oneline --all -- python/tests/unit
(no output)
```

Every Python test lives under `python/packages/*/tests/`, which the same filter already covers via `python/packages/**`. So the entry matches nothing — it neither triggers the workflow nor can it ever.

The cost is not runtime. A `paths:` list is documentation of what a check watches, and a contributor asking "will my change run coverage?" reads `python/tests/unit/**` as "unit tests live there". They don't, so the list describes a layout the repository does not have.

### Description & Review Guide

- **What are the major changes?** Two lines removed from `.github/workflows/python-test-coverage.yml`.
- **What is the impact of these changes?** None on what runs: the pattern never matched a file. Coverage still triggers on `python/packages/**`, `python/scripts/workspace_poe_tasks.py`, `.github/scripts/python_check_coverage.py`, and the workflow file itself.
- **What do you want reviewers to focus on?** Whether the entry is a placeholder for a planned move of tests out of per-package directories. If so, closing this and adding the directory when the move happens keeps the two in sync; if the move is not planned, the two lines are noise in a file people read to understand CI.
