## PR 描述

### Motivation & Context

`python/packages/lab/pyproject.toml` declares two console scripts:

```toml
[project.scripts]
gaia_viewer = "agent_framework_lab_gaia:viewer_main"
lightning = "agent_framework_lab_lightning:main"
```

The `lightning` target does not exist. `lightning/agent_framework_lab_lightning/__init__.py` defines one public name, `AgentFrameworkTracer` (`__all__ = ["AgentFrameworkTracer"]`), so installing `agent-framework-lab[lightning]` produces a `lightning` executable that fails on import instead of running. The two `main()` functions in the package live in `lightning/samples/train_tau2_agent.py` and `lightning/samples/train_math_agent.py`; neither is importable as `agent_framework_lab_lightning:main`.

The sibling entry is fine: `viewer_main` is defined in `gaia/agent_framework_lab_gaia/` and re-exported from its `__init__.py` (line 8, listed in `__all__` on line 25).

### Description & Review Guide

- **What are the major changes?** Deletes one line: the `lightning` console script. Nothing else moves — no import, no package, no `__init__`.
- **What is the impact of these changes?** `pip install "agent-framework-lab[lightning]"` no longer advertises a command that cannot start. The `lightning` extra and the `agent_framework_lab_lightning` package itself are untouched; library users import `AgentFrameworkTracer` exactly as before.
- **What do you want reviewers to focus on?** Whether a `lightning` CLI is planned. If it is, the fix should be a real `main()` in `agent_framework_lab_lightning` rather than removing the entry — say so and I will implement it instead. A command that raises `ImportError` the first time a user types it is the worse of the two states, which is why this PR takes the removal path.
