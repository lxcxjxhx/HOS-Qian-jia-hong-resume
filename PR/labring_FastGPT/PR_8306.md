## What this changes

Four `ko-KR` namespaces are missing keys that `en`, `zh-CN` and `zh-Hant` all define, so Korean users see the raw key wherever the UI reaches one of them. This adds the 79 missing translations:

| namespace | keys added | what they cover |
|---|---|---|
| `account_info` | 59 | the account-deletion flow: the notice page, the waiting-period copy, verification-code send/resend, WeChat QR verification, the team-facing pending/finalizing states |
| `account_team` | 8 | the team audit-log entries for submitting, cancelling and finalizing a deletion, plus `admin_delete_user` |
| `common` | 9 | `code_error.account_cancellation_pending`, its `team_error` sibling, the six `core.dataset.error.tag*` messages, and `error.operation_too_frequently` |
| `workflow` | 3 | the three `question_classification_default_*` labels |

## How the gap was measured

Keys were compared per namespace against `en` as the reference, after folding i18next plural suffixes (`_one`, `_other`, …) so that a language without a plural category is not reported for lacking one:

```text
account_info: en 129 keys — zh-CN 0 missing, zh-Hant 0 missing, ko-KR 59 missing
account_team: en 418 keys — zh-CN 0 missing, zh-Hant 0 missing, ko-KR  8 missing
common:       en 1408 keys — zh-CN 0 missing, zh-Hant 0 missing, ko-KR  9 missing
workflow:     en 389 keys — zh-CN 0 missing, zh-Hant 0 missing, ko-KR  3 missing
```

`zh-CN` and `zh-Hant` come out at zero on all four, which is what makes this a gap in one locale rather than keys that are intentionally English-only. The remaining `app` / `dataset` / `skill` differences are plural pairs only (`app_count_one` / `app_count_other`), which Korean does not need, so they are untouched.

After the change, `ko-KR` has no missing stems in those namespaces, and `node scripts/check-i18n-resource-loaders.mjs` still reports the loaders are up to date.

## About the wording

I translated from the English strings, keeping the terminology the file already uses — `계정` for account, `팀` for team, `검증 코드` for verification code, `소유자` for owner, `에이전트` for app/agent — and kept the `{{seconds}}` / `{{time}}` / `{{provider}}` placeholders intact. A native speaker should still read them before release; I would rather flag that than claim otherwise.
