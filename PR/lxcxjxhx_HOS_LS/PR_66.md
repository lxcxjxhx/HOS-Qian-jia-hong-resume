## PR 描述

## 问题

HOS-LS 扫的是 AI 生成代码的安全性，但仓里没有 `SECURITY.md`。想报「扫描器自身的洞」的人只能开公开 issue —— 而公开 issue 会把攻击面直接摊在台面上。

## 写了什么

按这个项目的两件事分开列：

**扫描器自身**
- 扫描时执行了被扫描代码（导入、构建、运行）
- 路径逃逸（读目标之外、写报告到输出目录之外）
- LLM API key / 代理凭据进入日志、报告、缓存
- 报告可被伪造：哈希链可裁剪、可重放

**判定结果**
- 规则误判导致漏报，且可复现
- **LLM 环节的提示注入** —— 被扫描代码里的注释或字符串让 LLM 改变结论。这是本项目的核心攻击面，值得单列
- 可复现的严重级别错配

**明确排除**：被扫描项目自身的漏洞（那是扫描对象）、依赖库已知漏洞、规则表里写明的取舍（走 feature request）、需要管理员权限的本地提权。

末尾一句说明本策略只覆盖安全问题，许可与再分发见 `CONTRIBUTING.md` 的 AGPLv3 一节 —— 避免两处规则打架。
