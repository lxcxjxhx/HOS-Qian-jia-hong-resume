`bin/lib/validate.mjs` 的三个健壮性缺口，分两个 commit：

## Commit 1: `da323b0` — 双向校验 + 缺失 hook 不再崩溃

**缺口 1：`COMMANDS` 单向校验**
只检查清单里的文件是否存在，不检查 `commands/` 目录下是否有清单外文件。新增 command 忘记更新 `COMMANDS` 数组时 `validate` 静默通过，校验器无法发现自己的清单已过时。
→ 改为双向：复用 `walkFiles()` 扫描实际文件，与清单求差，多余文件报 `Unlisted command file`。

**缺口 2：`hooks/session-start` 缺失时未捕获异常崩溃**
`chmod(...).catch(() => {})` 吞掉 ENOENT，随后的 `readFile` 直接抛出——CLI 打印原始堆栈，而不是走 `errors[]` 汇总路径。
→ hook 读取统一走 `readFileInto()`（失败进 `errors[]`）；`chmod` 失败也报错而非静默丢弃。

复现（改动前）：
```
mv hooks/session-start hooks/session-start.bak
npm run validate   # 期望 FAIL 走 errors[]；实际抛未捕获 ENOENT + 堆栈
```

## Commit 2: `c03e517` — markdown 链接校验扩展到 skills/commands/agents

链接校验只覆盖 3 个文件（README×2 + docs/platforms.md），而 `skills/*/SKILL.md` 有 **11 处本地相对链接**（如各 skill 的 `original-texts.md`）完全在校验盲区——#58 那类目录结构调整可能静默弄断它们。
→ 扩展到三个目录下全部 `.md`；当前 11 处链接全部有效，`npm run validate` 保持绿。
