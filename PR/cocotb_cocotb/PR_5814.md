## PR 描述

docs: document when plain pdb works (terminal-based simulators)

Closes #4314

The "Attaching a Debugger -> Python" section said that plain
``pdb.set_trace()`` is "frequently not possible" because simulators
interfere with ``stdin``, and only documented the ``remote_pdb``
workaround. That is true for GUI-driven simulators, but misleading for
terminal-based ones.

On terminal-based simulators (Icarus Verilog, Verilator, GHDL, NVC),
``stdin`` passes through to the embedded Python interpreter, so
:func:`breakpoint` / ``pdb.set_trace()`` work directly and the debugger
is driven from the terminal running the simulation. This distinction was
made by @ktbarrett in #4313 ("debugpy ... useful for debugging
non-terminal applications like most commercial simulations").

Changes:

- ``docs/source/troubleshooting.rst``: replace the blanket "frequently
  not possible" statement with an explicit per-simulator-type breakdown
  (terminal-based vs stdin-controlling), and add a ``debugpy`` link
  target alongside ``remote_pdb`` for the TCP-debugger alternative.
- ``docs/source/library_reference.rst``: soften the "often unusable"
  phrasing in the ``COCOTB_PDB_ON_EXCEPTION`` note the same way and
  cross-reference the troubleshooting section.
- add ``docs/source/newsfragments/4314.doc.rst``.
