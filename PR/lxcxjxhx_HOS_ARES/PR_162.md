## 问题

同一个 `--out` 跑第二次（openapi 靶场，实测）：

```
capsules/   2 份 → 4 份
verify_chain  False          ← 两个链头，order_chain 拿不到唯一头
findings.json 仍只引用 2 份    ← 报告说"2 份"，盘上 4 份
```

capsule 是内容寻址的：两轮 `created_at` 不同 → 哈希不同 → 文件共存；每条链各有自己的
genesis（`prev` 全零）。B150 在 bench 上修过同一件事，主命令 `run` 一直没修。

顺带撞见第二条：报告里的复现路径写死 `out/capsules/…`，`--out` 一旦不是默认值，
印出来的就是一份不存在的文件。B149 修了文件名，这一轮才修到目录。

## 改法

- `cmd_run` 开跑前检测 `<out>/capsules/*.json`：非空即拒（exit 2），
  **在花掉一轮时间之前**，且不碰任何已有产物
- 报告新增 `capsule_dir`，由调用方传真实目录；`demo` 也传自己的（它的报告以前同样指错）
- 平台汇总的"证据份数"改为按**结论引用的** capsule 数算，不数目录文件

## 效果

```
拒绝重跑：…/run/capsules 里已有 2 份 capsule。
  证据是内容寻址的：同一目录跑两次会变成两条链，报告里的份数也对不上盘上。
  换个 --out（例如 out/run-2），或先把上一轮移走（mv out/run out/run-1）。
exit=2；findings.json / report.md / capsules 逐字节未变

换 --out run-2 → 正常出 2 份，旧目录的链仍能过 verify-chain
report.md → `veripen replay --capsule <真实 out>/capsules/<sha>.json --mode offline`
```

## 一个没做的事

默认 `--out` 仍是固定路径，所以"再跑一遍"要手动换目录。要支持同目录多轮，得按
`run_id` 分目录——那会改 `plan-veripen/06`、`09` 里的路径示例（**冻结包**，
需单独 PR + operator 确认）。本轮刻意不动，已登记 H31 §2.3。
