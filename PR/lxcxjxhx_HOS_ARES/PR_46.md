## PR 描述

## 这一批是什么

控制台是「看和审」，不是「改」。三条硬约束写进代码，不写进文档。

## 三条硬约束

| 约束 | 怎么保证 | 怎么验 |
|---|---|---|
| **只读** | 写方法用 `add_api_route` 显式注册为 **405**（不是 404——路径存在、只是不许写） | POST/PUT/PATCH/DELETE 四种逐条测 |
| **路由不写死** | 页面路径 = `UI_PREFIX + op_id`，可整体重绑定 | 换路径不改代码的测试 |
| **绑定页只给摘要** | 只给 ref/标签/来源/置信档/TTL/模板哈希，模板正文永不出现 | 断言响应里搜不到模板 |

第三条尤其重要：`ui.routes` 是**攻击面地图**（05 §7 把它定为 confidential），
所以它不只不显示模板，还自带 `template_visible: false` / `exportable: false` 的自我声明。

## 降噪用公式，不是感觉

```
priority = 3×severity + 2×strength + 1×replay + 1×new − 3×silenced − 2×rolled_up
```

按队列分桶（now / week / low / silenced），同分按 `(oracle_id, template_sha256)` ——
**不用随机 ulid**（不可比）。这条被专门测过：同分的两条按 oracle 名字排，不按 id。

「看起来严重的先」会退化成「标题里有'高危'的先」——那是标题排序，不是风险排序。
