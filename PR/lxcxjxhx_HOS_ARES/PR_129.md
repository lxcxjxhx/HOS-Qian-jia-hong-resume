## 三件事

1. **`RenderThread`**：浏览器整个生命周期放在**没有事件循环**的线程里。
   playwright sync API 一旦检测到 running loop 就抛错——控制台是 FastAPI，迟早踩。
2. **分派**：`cmd_run` 按 `cls.needs_render` 选传输；渲染线程按需创建、结束关闭，
   请求数一并计入报告。
3. **查询串补齐**：发现来的面模板是 `/search`、参数是 `q`，不补 query 载荷根本发不出去。

## 三个真坑（都写进 ledger）

| 坑 | 表现 | 修法 |
|---|---|---|
| `urlencode` 把空格编成 `+` | 前端 `decodeURIComponent` 不还原 → 属性名损坏 → **假 REFUTED** | 用 `quote`（空格 → `%20`） |
| `<img onerror>` 依赖图片加载失败 | 目标对任意路径返回 200 → 图片"加载成功" → **假阴性** | 改 `<svg onload>` |
| `assertion.expected` schema | 写字符串 → capsule 构造 ValidationError | 用 `dict[str, list[int]]` |

前两个都属于"**判否是假的**"——比漏报更危险，因为它们看起来像"已经查过、没问题"。
