## 背景

`profiles/demo-a|demo-b` 早就写好了 assets / scope / selectors / oracles / 审批策略，但 `cmd_platform` 至今靠 `--targets` 直给 —— **档只是躺在那里的 YAML**。

企业级的入口不是"能传一串地址"，是"按客户档跑"：档里写着允许打哪些面、哪些动作要人批、engagement 叫什么。

## 改动（只动 `cmd_platform`，不动 `cmd_run` 契约）

| 项 | 行为 |
|---|---|
| 资产来源 | `--profile` 与 `--targets` **二选一**；同时给直接退出 2，不静默取其一 |
| 符号 → 地址 | `profile.asset_env` 给出变量名（`VP_ASSET_<ID>`）；缺失则 `assert_resolvable` 抛错、退出 2 并列出需要注入的变量名 —— **fail-closed，不猜地址** |
| oracle 白名单 | `exclude = 全部 oracle − profile.enabled`（白名单翻黑名单，`cmd_run` 的 `--exclude` 契约不变） |
| 审批 | `oracles.needs_approval` 非空即**自动要求审批**，不再依赖手工 `--require-approval`；`--approve` 仍是"谁签了字"的唯一开关 |
| 报告身份 | 写客户档名 / `customer_id` / `engagement_id` / `profile_hash` 前 12 位 / 档策略统计 |
