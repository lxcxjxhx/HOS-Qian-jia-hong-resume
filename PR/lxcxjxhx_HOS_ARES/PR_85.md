## PR 描述

## 缺陷

报告里每条发现的"面"显示成 `route://` —— **只有 scheme，没有可辨识部分**。

根因：`FindingView.route_short` 取 `route_ref[:8]`，而 `route://` 恰好就是 8 个字符。截断位置正好落在分隔符之后，于是所有发现的"面"长得一模一样。

## 修复前后

```
- 资产 `127.0.0.1` · 面 `route://`（contract）              ← 修复前
- 资产 `127.0.0.1` · 面 `route://contract/5ab365e3`（contract）  ← 修复后
```

## 改法

按 `scheme + source/ + id[:8]` 拼，而不是整体截断：

| 行为 | 说明 |
|---|---|
| 来源段完整保留 | 能看出 `contract` / `observed` / `crawl`，这是该字段唯一的信息量 |
| id 只留 8 位 | **完整 id 不透出**，脱敏不放松 |
| 无 scheme 的 ref | 仍走原逻辑（前 8 位），行为不变 |
| 空 ref | 返回空串（渲染层自己补 `-`） |

`route_short` 被四处使用（`json` / `sarif` / `markdown` / 未验证节），改一处全生效 —— 这也是选它而不是在每个渲染点各改一次的理由。
