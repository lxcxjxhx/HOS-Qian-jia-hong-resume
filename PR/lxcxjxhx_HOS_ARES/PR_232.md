## PR 描述

feat(delivery): 交付材料的第一步就跑不通（Windows 上没有 make）

## 判据

```
$ make doctor
'make' is not recognized as an internal or external command
```

而 `docs/delivery/quickref.md` 的「8 条命令」全是 `make …`。**我们同时发 Windows 的
exe 与安装包**——那台机器上往往没有 make，文档第一步就走不通。

顺带查出：`make up`（第一条命令）在 Makefile 里**根本不存在**。

## 改法

新增 [tasks.py](scripts/tasks.py)：纯 stdlib 的任务转发器，与 Makefile **同名同义**，
12 个任务（doctor / lint / verify / verify-all / demo / demo-alt / demo-offline / bench /
verify-report / replay-offline / exec-isolation / console）。

```
$ python scripts/tasks.py --list          # 列全部
$ python scripts/tasks.py lint            # 合计 7 项：ok 7  fail 0
$ python scripts/tasks.py doctor          # 与 python -m veripen_cli.cmd_doctor 同结果
```

交付材料补上跨平台入口；`make up` 换成真实存在的 `console`。

## 新增的用例（4 条）

```
文档里每个 make 目标必须真在 Makefile 里存在着   ← 抓出 `make up`
每个文档目标必须有同名 tasks 任务（跨平台）      ← 抓出未来新增的目标
必备任务齐备（doctor/lint/verify/demo/bench）
未知任务 exit=2
```

顺带修了一条被这次改动打破的旧用例（速查页“至少 8 条命令”按 `$ make` 计数 → 改成
`$ make` + `$ python scripts/tasks.py` 两种写法的总数）。
