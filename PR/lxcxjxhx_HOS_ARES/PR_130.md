## 为什么值得做

两条都能让脚本执行，但：

| 定性 | 含义 | 修法 |
|---|---|---|
| `reflected` | 服务端把载荷原样回了 | 输出编码 |
| `client_side` | 前端把不可信数据拼进 sink | 改 sink / 用安全 API |

此前两者给出一模一样的结论——那等于把两个不同缺陷合成一个。

## 两个自造坑（都写进 ledger）

1. **`RAW_LIMIT` 忘了在 `browser.py` 定义**（我把它插到了 `render_transport` 的注释旁），
   `response.text()[:RAW_LIMIT]` 抛 `NameError`，又被宽泛 `except Exception` 吞成空串
   → 原始响应永远空 → **所有页面都被判成 `client_side`**。
   已让 `NameError/AttributeError/TypeError` 直接抛：**代码错误不许伪装成"取不到"**。
2. 标记位求值早于 `onload` 回调 → 假阴性；读之前 settle 200ms。

第 1 条尤其值得记住：一个静默 except 把"代码写错了"变成"判定结果看起来正常"。
