## 问题

上一批把报告里的复现路径修对了，但那条命令本身还是跑不通：

```
veripen replay --capsule out/capsules/<hex>.json          # 报告印的
  replay: FAIL: live 模式需要真实靶场与 transport 注入      exit=1

veripen replay --capsule … --mode offline                 # 退一步
  replay: FAIL: offline 模式需要 capsule 内的响应夹具       exit=1
```

两个模式都是死胡同。而真正该报的那件事被另一件事盖住了：

```
run 产出的 7 份 capsule，离线重判全部 assertion_not_reproduced
csp/frame/nosniff 的断言其实是 fingerprint={"absent": true}
—— replay 算不出 absent（capsule 不存正文与响应头）
```

把"没算"报成"断言未被复现"，读者只会读成"结论被推翻"。这是同一个词背了两件事。

## 改法

- `_fingerprint_verdict` 返回 `(holds, missing)`：算不了的键单独报
  `predicate_not_recomputable:<keys>`；算出来是假的仍走 `assertion_not_reproduced`
- `--mode offline` 接通：不发包，用证据里存的状态与 body 哈希重跑判定，打印算过的谓词
- 退出码：`0` = 跑完（含"重算不了"/"无结论"），`1` = 证据与结论矛盾
- 报告印 `--capsule … --mode offline`，附录写清两种模式各能说什么

## 这笔账记下的真问题（账本 `open`）

capsule 不存响应头 → header 类 oracle（csp/frame/hsts/nosniff）的结论**无法由证据重算**，
`absent` 永远落 not_recomputable。要根治得二选一：把响应头存进 capsule（改 06 §7 红线），
或让 replay 能调 oracle 的 judge（core→oracles 反向依赖）。这不该偷偷做掉。

回滚：单提交 revert（offline 重新变成死胡同，"重算不了"重新混进"断言未被复现"）。
