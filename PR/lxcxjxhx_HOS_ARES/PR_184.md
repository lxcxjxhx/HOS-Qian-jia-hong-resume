## PR 描述

## 问题

`check_lock_snapshot` 只判断 `snapshot_sha256` 有没有 64 位，而 `Registry()` 是空的——
那份 sha 就是**空对象 `{}` 的哈希**（`44136fa355b3…`）。

于是这条检查与“锁完好”毫无关系，永远绿。

一个永远绿的检查比没有检查更坏：18 个绿勾里混进一个装饰，读者会以为某项被验过了。

## 改法

| 情形 | 现在的结论 |
|---|---|
| 没有插件（锁空） | **skip**，写明“0 条，没有可验的东西” |
| 有插件且 sha 与按 pin 重算一致 | OK（`N 条 · sha=…`） |
| 有插件但重算对不上 | **fail** + fix（锁文件可能被手改） |

- 新增 `registry.lock_sha(pins)`：把“按 pin 算 sha”的配方收成一处，
  `Registry._lock_sha` 与 doctor 共用；doctor 用**独立复算**而不是相信现成字段
