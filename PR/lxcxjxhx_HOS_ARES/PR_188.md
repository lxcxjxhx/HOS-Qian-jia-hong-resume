## 判据

```
DEFAULT_OFF（policy）   = {mass_assignment, rate_limit_absent, xss_stored_probe}
run 的 DEFAULT_EXCLUDE  = rate_limit_missing, mass_assignment, xss_stored_probe
                          ^^^^^^^^^^^^^^^^^^ 没有这个 oracle（真名 rate_limit_absent）
hunt 的默认排除          = rate_limit_absent, …           ← 是对的
```

于是 policy 明确“默认关闭”的压力类，从来没被默认排除。

## 效果（同一靶场，只有一条 `rate_sensitive` 面）

```
旧默认  可跑 oracle 1 个 → findings=[rate_limit_absent] · rc=0     ← 压力探测被默认执行
新默认  可跑 oracle 0 个 → rc=1「没有可跑的 oracle」
```

## 改法

- `DEFAULT_EXCLUDE` 修正为 `rate_limit_absent,mass_assignment,xss_stored_probe`
- 把**不变量**写成用例（不只是改那个字符串）：
  1. 默认排除表里的每个 id 都必须是真 oracle（拼错即红）；
  2. `DEFAULT_OFF` 必须被默认排除覆盖（否则“默认关”是空话）；
  3. run 与 hunt 的默认排除必须同口径；
  4. 把当年的错名 `rate_limit_missing` 钉进用例，防止再写回去。
