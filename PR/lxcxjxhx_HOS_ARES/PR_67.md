## 本批判据（`H07` B53 / `H03 §5`）

A 五张表始终在（空写「（无）」） · B 两次生成逐行相同 · C 拒绝/异常互斥 · D 冲突表接 B51 · E 只陈述事实 · F 可插入报告。

## 为什么这一节几乎免费但要单独做

客户真正怕的不是"AI 挖不到洞"，是"AI 乱动了我没看见"（`32 §2.3`）。
数据全在 `task_events` 里，缺的只是"把它摊开"。

| 表 | 来源 | 缺数据时 |
|---|---|---|
| 动作账 | task_events（seq/kind/目标/结果/耗时） | 「（无）」 |
| 预算账 | 五预算 used/limit | 「未提供」（不是 0） |
| 拒绝账 | `kind=approval` 或 `err_class=approval` | 「（无）」 |
| 冲突账 | B51 `conflict_report()` | 「（无）」 |
| 异常账 | 失败且**非审批**的事件 | 「（无）」 |

两个刻意的设计：
1. **拒绝与异常互斥**——审批被拒是一条正常发生的拒绝，不是"出错"，重复计会让人以为系统不稳；
2. **预算缺失写「未提供」**——写 0 会被读成"没用过"。
