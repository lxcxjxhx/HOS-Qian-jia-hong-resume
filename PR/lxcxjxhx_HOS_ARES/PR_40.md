## 三条取证纪律，写进代码而不是文档

1. **200 不是证据**：变体必须带回「只有该身份才看得到」的标记字段。
   拿不到 → `INCONCLUSIVE(no_discriminating_field)`。这是 J 系列 FP 的唯一来源。
2. **没有 control 不许出洞**：无效签名必须被拒，否则无法证明服务器在验签。
3. **token 只存摘要**：alg / claim 名 / 签名长度与前缀。签名原文绝不入证据（有测试断言）。

## O / M / S / X（20 §3–§6）

24 项检查单落地为数据：**auto 15 / semi 4 / manual 5**。
其中 6 条给出纯函数判定：O1 回调、O5 code 重放、S1 会话固定、M1 握手原因、M7 单向认证。

两个刻意的设计：
- **M1 与 M3 不能混**：自签证书导致 `unknown ca` 时，M1 其实没被测到 → `INCONCLUSIVE(measured_M3_not_M1)`；
- **手工项必须写「为什么手工」**（有测试强制），SAML 四条明列未覆盖。

## 实现中修掉的三处真实缺陷

1. `{{jwt:}}` + JSON 的占位符写成了外层提前闭合 → 改为 JSON 内嵌 + **配平扫描**；
2. 裸标记 spec 会掉进旧版解析器抛 `ValueError` → 原样返回，不编造；
3. control 的「无效签名」改为**保留长度、破坏 base64url**——否则脆弱靶场的
   最低限度 plausibility 检查会一并放行，判定退化成「整站不验签」，说不出具体是哪个缺陷。
