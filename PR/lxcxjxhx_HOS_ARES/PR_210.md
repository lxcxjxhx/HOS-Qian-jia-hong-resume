## PR 描述

feat(lint): 锁与 pyproject 的一致性——离线包少一个包，客户内网才发现

## 判据

`requirements.lock` 是**内网离线装的唯一来源**（A3「内网能装」），它与 `pyproject`
是同一份事实的两个出口，却**没有任何检查**。两条岔路都只在客户内网显形：

```
新加运行期依赖只改 pyproject  → 离线包少一个包（B200 的 jsonschema 正是这个剧本）
锁里钉的版本低于 pyproject 下限 → 本地能跑，客户装出来是旧版
```

## 改法

新增 `scripts/lint/lock_sync.py`，三查：

| 查 | 结论 |
|---|---|
| `pyproject` 的运行期依赖在锁里必须 pin | 缺 → FAIL 并点名 |
| 锁里的版本必须满足 `pyproject` 下限 | 不满足 → FAIL，写出“锁 X < 下限 Y” |
| 锁里有、`pyproject` 没有 | 允许（传递依赖），但列出来供人工确认 |

包名按 PEP 503 归一（`PyYAML` = `pyyaml`，`-` = `_`）。接进 `scripts/verify.py` 清单，
所以 CI 与本地都跑。

## 反向验证（这条闸门真能红吗）
