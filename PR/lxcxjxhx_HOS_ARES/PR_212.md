## PR 描述

fix(docker): 镜像里的依赖清单是手写的，五条漏了一条

## 判据

```
Dockerfile:  RUN pip install --no-cache-dir pydantic PyYAML fastapi uvicorn
pyproject:   ['pydantic', 'PyYAML', 'fastapi', 'uvicorn', 'jsonschema']
差集（漏装）: ['jsonschema']
```

`jsonschema` 正是 B200 刚登记的运行期依赖（`veripen_core/playbooks.py` 直接 import，
`cmd_platform` / `cmd_parity` 都会走到）。容器里一加载演练剧本就 `ModuleNotFoundError`。

**同一份依赖，Python 侧有一份、容器侧还有一份手写副本，而副本漏得更多**——
两处出口的老问题，这次换了介质。

## 改法

| 位置 | 改动 |
|---|---|
| `Dockerfile` | `COPY pyproject.toml requirements.lock ./` + `pip install --no-cache-dir -r requirements.lock` |
| `scripts/lint/lock_sync.py` | 新增 `dockerfile_problems()`：Dockerfile 里装依赖必须走锁；**手写清单直接 FAIL 并点行号** |
| `tests/unit/test_lock_sync.py` | +3 条：手写清单红 / 走锁绿 / 真仓 Dockerfile 必须走锁 |

锁里带 dev 的 `pytest`，镜像多几 MB——换“只有一处真相”，这个交换值。

## 这条的教训

B200 在 Python 侧抓到 `jsonschema` 漏登记；**同一条依赖在容器侧还有一份手写副本**。
修一处不够——要把“同一个事实的所有副本”一次找齐，并让闸门盯着剩下的那些。

回滚：单提交 revert（Dockerfile 回到手写清单；闸门检查一并回退）。
