## PR 描述

## 问题

07 §300/§321、01 §140、18 §107 三处都写着“缺 `requires` 则 BLOCKED”，全仓没有代码读它。实测只给主身份时：

```
idor_cross_account（requires auth:secondary）
  → undetermined  baseline_abnormal        ← 读者分不清“目标没问题”与“我缺输入”
```

## 改法（默认关，行为不变）

- `unmet_requirements(oracle, *, token, oob, approval)`：只回答“这一轮满足不了哪些”
  - `auth:primary` / `token:real` = 有 token；`auth:secondary` 当前一律不满足
  - `oob:listener` / `approval:*` 由调用方显式给
  - **未知前缀按不满足处理**（fail-closed）：宁可少判，不可假判
- `harness.run(..., strict_requires=True)`：缺输入时**一个请求都不发**就返回
  BLOCKED，reason `missing_input:<req>`
- `veripen run --strict-requires` 打开它

默认关是刻意的：一开就会让 bench 的多身份用例集体变 BLOCKED、指标当场失真。

## 效果（同一靶场两次跑）

```

--strict  idor_cross_account → undetermined  missing_input:auth:secondary   （该条 0 请求）
```
