## 改了什么

三份治理文件，内容按这个仓的实际做法写：

- **`CONTRIBUTING.md`** —— 环境、`scripts/verify.py` 是本地与 CI 的**同一份定义**（所以别在别处再写一份命令列表）、分段跑法、提交规范、PR 检查项。
- **`SECURITY.md`** —— 私有报告入口、响应时限（确认 3 个工作日 / 评估 7 个工作日）、在/不在范围内、以及「这是验证工具不是扫描器」的边界说明。
- **`.github/ISSUE_TEMPLATE/`** —— bug 与 feature 两份表单；bug 表单开头把安全问题挡到 SECURITY.md，并强制填复现步骤与 `veripen doctor` 输出。

## 为什么这么写

- 提交规范照现有历史：Conventional Commits + 中文，描述写「发现的问题」而不是「改了什么」——这个仓的 log 当事故记录用。
- SECURITY.md 把「判定被绕过」和「证据链可失效」列为在范围内，因为这两件事是纯函数内核的核心承诺；把「依赖库已知漏洞」排除，因为那该报上游。
- issue 表单强制 `veripen doctor` 输出，因为 25 项自检里 skip 和 fail 是两回事，缺了这项没法判断环境。
