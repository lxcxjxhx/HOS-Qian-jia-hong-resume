## 三处跨边界传参的坑（都实测踩到）

1. **`--` ≠ `--exec`**
   `--` 之后的参数被 WSL 拼成一条字符串交给登录 shell。`python -c print("x")` 到那边成了 bash 语法错误，
   报出来像「容器起不来」。第一次发现时以为镜像拉不下来。
2. **超时不能只杀宿主侧客户端**
   podman 由 conmon 托管，杀掉 `wsl.exe` 不等于容器停。改为容器内前置 `timeout N`（coreutils），
   宿主侧 `timeout_s + GRACE_S` 只兜底。两边同时开枪 = 容器来不及留下 124。
3. **路径归谁**
   `--mount src=` 用引擎那一侧路径，`C:\a` 在发行版里不存在。先问 `wslpath -a`，问不到按盘符兜底。
   另外 `wsl -l -q` 的输出是 **UTF-16LE 带零字节**，直接 utf-8 解码会得到 `U\x00b\x00…`，
   拿去 `-d` 必报「发行版不存在」。

## 判据怎么成立（不是"装了 docker"）

容器档下真起一个容器，对着**宿主真目录**看两件事：

- 容器内 `touch /tmp/x` → 宿主上 `x` 不存在（命名空间隔离成立）
- `--mount type=bind,src=<宿主管>,dst=/work,readonly` 后容器 `touch /work/x` → 失败，宿主目录仍空

`isolation` 如实分档：`container`（docker / wsl-podman）与 `job-object`（Windows 资源受限）不混。
没有运行时仍冒泡成 BLOCKED，**不降级到裸跑**。

## 边界（不隐瞒）

- 需要那台机器上有 WSL 发行版 + podman：
  `wsl -d <发行版> -- sudo apt install podman uidmap slirp4netns fuse-overlayfs`
- 宿主 docker 仍优先；两者都没有时退回 Job Object，`isolation` 会如实写成 `job-object`
- 容器级**并行**（E5 的另一半）仍未做：执行体有了，缺「每任务一容器 + 配额分发」的调度
