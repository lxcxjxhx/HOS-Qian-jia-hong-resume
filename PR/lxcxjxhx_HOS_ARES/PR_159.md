## 问题

跑完 44 例 × 3 轮，`out/b12` 下**没有** capsules 目录，bench.md 却写着：

```
证据：capsule 123 份（sealed）· 重放通过 108 · 未复现 15
```

`capsule_id` 是真哈希、`replay_status` 是真重放——但那份证据**从来没有写进磁盘**。
读者拿到的是计数，不是一个能打开的文件。

同一轮还撞出两件让"复现不了"变成必然的事：

```
1) 同一个 --out 重跑一次
   r1/ 里堆到 123 个文件（三次运行各 41 份），三份链头混在一起
   verify-chain  breaks=120        ← 链全红，报告照旧写"123 份"
2) CORS 预检
   capsule 记 'GET'，实际发的是 'OPTIONS'
   重放照着 GET 打：501 → 200，PARTIAL
   → P-23 / P-24 / N-14 三条"永远复现不了"，被记成"判定不稳"
```

## 改法

- 每轮 capsule 用 `chain_capsules` 串成**一条链**，落盘到 `capsules/<run>/r<N>/`
- `<run>` 取本次运行的 UTC 时刻：重跑不混轮，报告份数 == 盘上份数
- `build_capsule` 按变体的 `method` 覆盖记方法；`StepParamsTransport` 按证据里的方法发
- bench.md 加两行：证据目录（含 `--verify-chain` 命令）、**未复现用例点名**
