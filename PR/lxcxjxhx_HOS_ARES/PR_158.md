## PR 描述

## 问题

多面之后链变长（每面一份 capsule），`verify_chain` 只查"相邻 `prev` 对得上"：

```
修前：删掉链头那一份 capsule，剩下的环彼此仍然自洽
  veripen evidence --verify-chain out/capsules/*.json
  chain ok=True root=1f57a9c7…            exit=0   ← 少了一份证据，校验器说"完整"
```

原因：期望的 `prev` 取自 `caps[0].prev`，也就是"这批自己的第一环"。中间缺条能抓，
**删头抓不到**——根断在半空，剩下的环自己跟自己接得住。

同一轮还发现报告里的复现命令指向不存在的文件：

```
report.md: veripen replay --capsule out/capsules/sha256:<hex>.json
盘上实际:  out/capsules/<hex>.json            ← 文件名的前缀是 `sha256:` 拼出来的幻觉
```

## 改法

- `verify_chain`：不给外部锚点（`root_sha256`）时，链头 `prev` 必须是全零，
  否则 `BREAK [0] 链头 prev=… 不是全零`；给了锚点仍允许只校一段子链
- `ChainReport` 带 `length` / `head_sha256` / `tip_sha256`，`--verify-chain` 打印
  `links= head= tip=`。报告里的 `root_sha256` 就是 `head`，两个出口能逐字对上
- 报告复现命令改用 `self_sha256` 拼路径（`save_capsule` 就用它命名）

## 一个边界（写进账本 `open`）

链尾被删，只有 capsule 文件时无法自证——没有外部锚点。现在靠**报告列出的证据全集**
对账：`findings[].evidence.capsule_id` 与盘上 capsule 必须逐一对上。报告本身若被改写，
需要报告层签名锚点，不在本轮。
