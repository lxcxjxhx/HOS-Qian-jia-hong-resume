## 背景

`H13` 落盘后第一批。用户指出：strix 面（自动化渗透）的能力都在库里，但**没有一条"给目标 → 自己跑完 → 出报告"的命令**。

## 做了什么

`veripen run --target … --openapi …`：契约解析 → 路由解析 → oracle 选择 → 执行 → capsule 封存 → 报告出具。

与 `cmd_hunt` 的分工：hunt 是人盯着跑只打印；run 是跑完给交付物（`report.md` / `findings.json` / `capsules/`），并且**没有可跑 oracle 时退出码非 0**。

## 期间挖出并修掉的真缺陷

**一条带路径参数的路由能让整份契约 0 条绑定：**

```
{id} → 规范成 {p}
→ planner 的 param_names 来自 operation.params（路径参数不在其中）
→ SymbolSource._render 判"未知符号"抛 SourceError
→ Resolver 记 sources_failed=['contract']
→ 0 绑定 / 0 oracle
```

真实目标的 OpenAPI 几乎必然有路径参数，所以这条链在生产上从来没通过过（只有无参数的靶场夹具覆盖）。

修法：`param_names` 为空时从模板兜底提取（与 `merge.py` 既有做法一致），保留"真正未知符号必须 loud 抛"的既有契约。

另外两处：
- `build_guard()` 抽到 `cmd_hunt` 两入口共用——第一版没装 GuardContext，6 个 oracle 全抛 `GuardMissing`
- 出网前设 `transport.oracle_id`，否则闸门按 oracle 放行时一律 `plan_denied`
