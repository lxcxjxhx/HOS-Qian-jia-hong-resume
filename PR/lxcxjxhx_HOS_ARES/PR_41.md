## PR 描述

## 这一批是什么

W3 开篇，也是**第一次按计划动 core**。一句话纪律：

> LLM 负责找，确定性工具负责证，路由层负责「在哪找」。
> 推论：模型只影响「跑不跑得到」，不影响「判定是什么」，也不影响「地址是哪来的」。

## 三个刻意的判断

1. **分段校验**：外层 `additionalProperties: false`，模型把 `skip_guard: true` 塞外层直接拒；
   `params` 整体交 oracle 的 `params_schema`，外层**不解析内层**。
2. **截断尾部优先**：`body[:4096]` 会把「为什么失败」整段切掉——
   渗透工具的失败原因几乎总在最后几行（错误码/摘要/退出统计）。按六步顺序头尾切片，全文落盘给 `persisted_ref`。
3. **schema 错误不计入「无新事实」**：模型给的调用不合法 ≠ 任务无进展。
   否则三次非法 JSON 就把任务判成「收敛」——那是最容易被误读成「没发现」的假象。
