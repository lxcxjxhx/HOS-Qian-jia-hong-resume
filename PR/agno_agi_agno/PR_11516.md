## Summary

Fixes #11513.

The database adapters' `Args:` blocks still name a `create_table_if_not_found` parameter, left over from when `get_sessions()`, `get_eval_runs()` and `get_user_memories()` accepted it. No signature in the repository takes it any more, so the docstrings describe an interface the code does not have.

This PR removes those entries and corrects the related ones that name an argument the signature does not carry.

```
agno/db/firestore/firestore.py          get_user_memories, get_eval_runs
agno/db/gcs_json/gcs_json_db.py         get_sessions, GcsJsonDb.__init__ (location)
agno/db/json/json_db.py                 get_sessions
agno/db/mongo/mongo.py                  get_sessions, get_user_memories, get_eval_runs
agno/db/mysql/mysql.py                  get_eval_runs
agno/db/mysql/async_mysql.py            _create_table (db_schema, read from self)
agno/db/postgres/postgres.py            get_eval_runs
agno/db/singlestore/singlestore.py      get_sessions, get_eval_runs
agno/db/sqlite/sqlite.py                get_sessions, get_eval_runs
agno/db/sqlite/async_sqlite.py          get_eval_runs
agno/db/dynamo/dynamo.py                get_user_memories (workflow_id)
agno/db/postgres/utils.py               is_valid_table, ais_valid_table (schema -> db_schema)
agno/db/singlestore/utils.py            is_valid_table (schema -> db_schema)
agno/client/a2a/utils.py                map_stream_events_to_{run,team_run,workflow_run}_events (user_id)
agno/knowledge/knowledge.py             search (model)
agno/os/utils.py                        format_sse_event (event_dict)
agno/vectordb/lightrag/lightrag.py      lightrag_knowledge_retriever (num_documents, mode, lightrag_server_url)
agno/vectordb/pineconedb/pineconedb.py  search (include_metadata)
agno/vectordb/singlestore/singlestore.py content_hash_exists (document)
```

Every removed line was matched to the docstring it sits in with `ast`, and the enclosing function was checked to have no parameter of that name before the line was dropped — an earlier pass that matched on text alone also deleted `create_table_if_not_found=True` from a call site, which is exactly the mistake this check prevents.

`libs/agno/tests/unit/test_db_docstring_args.py` now enforces the invariant: it parses every module under `agno/db` and fails when a docstring mentions `create_table_if_not_found` on a function that does not accept it. Against `sqlite.py` as it was before this branch it fails with both offenders listed (`get_sessions()` at 1840, `get_eval_runs()` at 3429); against this branch it passes.

Apart from that test the diff touches docstrings only: 19 modules, 5 insertions, 31 deletions, no code line changed, so no call site, default or behaviour moves.

A package-wide sweep found six more entries of the same kind outside `agno/db`, now also fixed here: `map_stream_events_to_run_events` and its team/workflow siblings named `user_id` instead of `agent_id`, `team_id`, `workflow_id`; `format_sse_event` named `event_dict` instead of `event`; `Knowledge.search` named `model`, which it neither accepts nor reads from kwargs; `lightrag_knowledge_retriever` named `num_documents`, `mode` and `lightrag_server_url` though it takes only `query`; `PineconeVectorDb.search` named `include_metadata` instead of `include_values`; and `SingleStoreVectorDb.content_hash_exists` named `document` instead of `content_hash`. After those, a sweep over `libs/agno/agno` reports no remaining entry of this kind — the 28 hits it still prints are docstring prose wrapped at the `Args:` indent ("Default", "Good", "Eg", "archive"), not parameter names.

One file the issue also lists is left alone on purpose: `agno/tools/decorator.py` `tool()` takes `**kwargs` and validates every name its docstring lists against its own `VALID_KWARGS` set before forwarding them to the `Function`, so its `Args:` block is the contract there, not drift.
