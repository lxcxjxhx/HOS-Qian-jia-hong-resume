## PR 描述

test: write the recipe file through tmp_path, not an open NamedTemporaryFile

`test_recipe_create_instance_accepts_valid_recipe_file` reopens the temp file while the writing
handle is still open:

```python
with tempfile.NamedTemporaryFile(mode="w", suffix=".yaml") as f:
    yaml.dump(content, f)
    recipe = Recipe.create_instance(f.name)      # reopen while `f` holds the file
```

On Windows that reopen is denied, so the test fails with

```
E   PermissionError: [Errno 13] Permission denied: 'C:\\…\\tmpbe3zo89x.yaml'
1 failed, 22 passed
```

The file itself is written correctly — checked on disk at 109 bytes while the handle is open — so
this is the sharing mode of the open handle, not a flush or ordering problem. Dumping to a closed
path removes the interaction entirely:

```python
recipe_path = tmp_path / "recipe.yaml"
recipe_path.write_text(yaml.safe_dump(content), encoding="utf-8")
recipe = Recipe.create_instance(str(recipe_path))
```

Same assertion, same thing under test (create from a *file path*), and the `tmp_path` fixture is
the pytest-recommended form for this.

Scope, stated plainly: this is a Windows-only failure, so there is no red→green to show in CI on
Linux — the whole file is `22 passed` on both sides there. Verified here by toggling only that
hunk on a Windows 11 box:

| | before | after |
|---|---|---|
| `tests/llmcompressor/recipe/test_recipe.py` | 1 failed, 21 passed | **22 passed** |

`import tempfile` was dropped because that was its only use in the file.
