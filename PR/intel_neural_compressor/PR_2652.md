`_print_trial_results_table` divides by the baseline as-is, so a negative baseline inverts the sign of the `Relative Loss` column while the `Status` column next to it stays honest. One-line fix plus the regression test.

## The bug

```python
# base_tuning.py, main
relative_loss_val = (baseline_val - trial_result) / baseline_val
```

Captured from `main` with a single trial per monitor:

| baseline | trial | better? | printed | status |
|---:|---:|:--:|---|---|
| −2.0 | −1.9 | yes | `5.00%` | ✅ PASSED |
| −2.0 | −2.1 | no | `-5.00%` | ❌ FAILED |
| 2.0 | 1.9 | no | `5.00%` | ❌ FAILED |

The two negative-baseline rows read backwards: the trial that passed is reported as a 5% loss, the one that failed as a 5% gain. Dividing by `abs(baseline_val)` gives the same numbers for positive baselines and flips only the negative ones:

| baseline | trial | printed after |
|---:|---:|---|
| −2.0 | −1.9 | `-5.00%` |
| −2.0 | −2.1 | `5.00%` |
| 2.0 | 1.9 | `5.00%` (unchanged) |
| 2.0 | 2.1 | `-5.00%` (unchanged) |

This is the same class of fix as #2601, which corrects the threshold for negative baselines (`baseline * (1 - tolerable_loss)`); without this line, that PR's `need_stop()` says "goal met" while the table above it reports a loss.

## The change

```diff
         if self.baseline is not None:
-            relative_loss_val = (baseline_val - trial_result) / baseline_val
+            # Divide by |baseline| so a negative baseline keeps the same sign convention as a
+            # positive one: a better trial reports a negative loss, matching the PASSED/FAILED column.
+            relative_loss_val = (baseline_val - trial_result) / abs(baseline_val)
             relative_loss_str = f"{relative_loss_val*100:.2f}%"
```

`relative_loss_val` is display-only — it is formatted into `relative_loss_str` and nothing else reads it — so nothing outside the table changes.
