## Description

Five docstrings in `neural_compressor/torch/algorithms/smooth_quant/utility.py` name arguments that the signature does not take. One file, one class of defect, +5/−10.

| function | docstring said | signature has |
|---|---|---|
| `cfg_to_qconfig` | `user_cfg`, `output_tensor_ids_op_name` | `tune_cfg`, `output_tensor_id_op_name` |
| `_dump_min_max` | `calibration_method` | only `calib_iter` |
| `calibrate` | `absorb_to_layer` | only `calib_iter`, `op_types` |
| `_absorb_scales` | `alpha_key` | only `layer_name`, `scale` |
| `transform` | `do_blockwise`, `init_alpha` | neither — `init_alpha` is a **key inside** `auto_alpha_args` |

Three of the five are leftover parameter tables from a refactor that moved the value somewhere else:

- `calibration_method` became a wrapper attribute (`self.q_func`), so it is no longer an argument;
- `absorb_to_layer` is now computed inside `calibrate` (`self.absorb_to_layer`) and returned, not passed in;
- `alpha_key` was folded into `SQLinearWrapper` when scales moved there.

The `transform` entries are the interesting ones: `do_blockwise` does not exist anywhere in the signature, and `init_alpha` is a dict key, so a reader who follows the docstring writes `transform(init_alpha=0.3)` and gets a `TypeError`. Rather than delete the explanation, I folded it into the `auto_alpha_args` entry, which is where the key actually lives:

```python
auto_alpha_args={..., "init_alpha": 0.5, ...}
```

For `cfg_to_qconfig` the two names were simply wrong: `tune_cfg` is the caller's tune config, and the parameter is `output_tensor_id_op_name` (singular `id`) — the plural spelling in the docstring matches `static_quant/utility.py`'s variant, which is where the copy came from.
