## Description

Three docstrings name a parameter the function does not take. Doc-only, +3/−3 in three files.

| file | function | docstring said | signature has |
|---|---|---|---|
| `torch/utils/block_wise.py` | `calibrate_block_and_update_inputs` | `raw_block` | `block` |
| `torch/utils/utility.py` | `validate_modules` | `modules` | `module_names` |
| `torch/export/export_hf.py` | `_export_hf_checkpoint` | `dtype` (the weights data type to export the unquantized layers) | `scheme: str \| None` — and the body passes it straight to `get_quant_config(scheme=scheme)` |

The export one is the one that misleads most: the docstring sends the reader looking for a dtype knob, while the argument actually selects the quantization scheme the checkpoint is written for. I replaced the description rather than only the name, because keeping "the weights data type …" under `scheme` would be worse than the missing name.

`validate_modules` also had its `Args:` entries indented one level too little (they line up with `Args:` itself); I left the indentation alone and changed only the name, so the diff stays a rename.

## Expected Behavior & Potential Risk

No runtime behaviour change: three docstrings now name parameters that exist in the signature. Nothing reads these strings at import time.
