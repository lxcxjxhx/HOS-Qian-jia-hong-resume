## 这个 PR 修的是我自己造成的问题

PR #17（补签名）改了 `convert_resume.yml`，触发全量重建。`resume.html` 一个字符没变，75 段正文却被从头译了一遍——免费端点只会回 429，于是闸门把 CI 判红：

```
[ERROR] 35 段在 6 轮后仍未翻译完成
[ERROR] 保留上一版 resume.en.html 不动，本次不产出更新
Process completed with exit code 1
```

耗时 **7 分 16 秒**后失败，而简历内容毫无改动。闸门本身是对的（不完整就不产出），错的是「没变也要重译」。

## 根因

翻译结果没有任何缓存。改动 workflow、改动转换脚本都会触发重建，而重建必然全量重译。免费端点对同一批重复请求的回应就是限流。

## 修复

| # | 改动 | 效果 |
|---|---|---|
| 1 | 在 `resume.en.html` 写入 `translation-cache: <sha256>` 标记 | 指纹一致时直接复用，**零请求** |
| 2 | `FORCE_RETRANSLATE=1` + `workflow_dispatch` 开关 | 需要重译时手动触发 |
| 3 | gtx 429 熔断：连续两次失败即熔断 60s 并轮换主机 | 本轮剩余段落直接走 MyMemory，不再对着同一堵墙撞 6 遍 |
| 4 | MyMemory 额度 40 → 100 | 缓存生效后极少用到，留足一次全量兜底 |

复用缓存前仍会校验 base64 逐字节一致、体积、中文残留比例——缓存产物坏了会自动重译。

## 顺带修一处静默污染

MyMemory 额度耗尽时，会把这段塞进 `responseData.translatedText`：

```
MYMEMORY WARNING: YOU USED ALL AVAILABLE FREE TRANSLATIONS FOR TODAY...
```

它**含拉丁字母**、**也不等于原文**，能同时骗过现有两道校验，最终会作为正文写进英文简历。现在显式拦截含 `MYMEMORY WARNING` / `QUOTA` / `INVALID` 的返回值并丢弃。
